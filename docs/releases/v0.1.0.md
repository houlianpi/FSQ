# FSQ v0.1.0 - Initial Alpha Release

FSQ v0.1.0 introduces an evidence-first agent harness for AI UI automation across Web, Android, Windows, and macOS.

This is the first public alpha. It is meant for evaluation, feedback, and early contribution, not as a 1.0 compatibility commitment.

## Highlights

- Describe a visible UI goal and run it through an AI-driven exploration loop.
- Capture screenshots, UI snapshots, ordered events, metadata, and reports as inspectable evidence.
- Generate a Run-local candidate Case from real execution facts, then review it before using it as a deterministic regression.
- Replay authored Cases deterministically without asking the model to rediscover every step.
- Diagnose platform, target, Provider, and command readiness with `fsq doctor`.
- Query Runs and open a self-contained offline HTML report.
- Use the local Control Plane for Workspace, Provider, Case, Run, and evidence workflows.

## Install

```bash
python -m pip install fsq-agent
```

The base package includes Python dependencies for all supported platforms. Host applications, browsers, devices, ADB, and Appium services remain external prerequisites.

## Platform backends

FSQ complements established automation backends rather than replacing them:

| Platform | Backend | Host prerequisite |
|---|---|---|
| Web | Playwright | Installed Chromium-family browser |
| Android | uiautomator2 | ADB and an online authorized device |
| Windows | pywinauto | Windows and an existing application |
| macOS | Appium Mac2 | macOS, an existing application, and a reachable Appium service |

## Supported scope

- Python 3.11–3.13 package metadata; see CI for the validated host/version matrix.
- Web through Playwright, Android through uiautomator2, Windows through pywinauto, and macOS through Appium Mac2.
- GitHub Copilot and Azure OpenAI Providers.
- Local Workspace state, Run evidence, static reports, and Provider configuration.

## Privacy and evidence sharing

FSQ stores UI screenshots, UI trees, logs, metadata, reports, and generated suggestions locally. These artifacts can contain application data. Review and redact `.fsq/runs`, screenshots, reports, logs, and Provider configuration before sharing them in issues, pull requests, demos, or support channels.

Do not publish tokens, API keys, authorization headers, cookies, device codes, account data, private URLs, device serial numbers, local paths, or unreviewed Run artifacts.

## Known limitations

- v0.1.0 is alpha software; public CLI, Case DSL, Provider, and UI details may evolve before 1.0.
- Host prerequisites are intentionally not installed by `fsq init`.
- Provider setup requires a supported GitHub Copilot or Azure OpenAI configuration.
- `case test --suggest` analyzes existing execution facts after one Case execution; it does not operate the UI a second time.
- Evidence quality depends on platform backend availability and target UI accessibility.
- Final release publication still requires running the [release acceptance checklist](../release-acceptance-checklist.md) against the final release commit and installed artifact.
