# Android UI Snapshot XML Compaction Design

## Goal

Reduce Android `ui_snapshot` / `uiTree` XML size while preserving enough page information for an agent to understand and act on the current Android screen.

The first implementation cycle targets only Android `UiAutomator2AndroidDriver.ui_snapshot`. It must keep the existing output contract, still returning a JSON payload with an `xml` string, but the XML should be compacted before it is exposed to dynamic agents, strict cases, or automatic evidence capture.

## Scope

In scope:

- Android `ui_snapshot` output generated by the uiautomator2 backend.
- Explicit `uiTree` calls and automatic Android `ui_snapshot` evidence artifacts, because both call the same driver method.
- Tool/capability description text for Android `uiTree`, including a clear statement that long text-like attributes are clipped.
- SPEC updates in the later `spec-driven` phase for the affected `core` and `models` Android snapshot requirements.
- Focused tests for Android snapshot compaction behavior.

Out of scope for this cycle:

- Web, Windows, and macOS snapshot behavior.
- New public parameters on `AndroidUiTreeParams`.
- New YAML or environment configuration for snapshot compaction.
- Changing artifact kind, artifact MIME type, or top-level output key names.
- Replacing XML with a locator JSON representation.
- Vision-based page understanding or AI element finding.
- List/recycler structural deduplication, viewport-only filtering, diff snapshots, or budget-driven subtree summarization. These remain follow-up strategies.

## Confirmed Strategy

The Android compact snapshot should apply a conservative pipeline:

1. Try source-level hierarchy compression when available.
2. Parse XML and normalize the hierarchy in process.
3. Remove low-value/default attributes.
4. Clip long text-like attributes to 50 characters.
5. Remove layout-only wrapper nodes by lifting meaningful descendants.
6. Remove empty nodes after cleanup.
7. Fall back to raw XML on parse or compatibility failure.

The implementation should be deterministic and should not depend on LLM context, previous snapshots, or runtime task intent.

## Proposed Design

### 1. Source-Level Compression Probe

`UiAutomator2AndroidDriver.ui_snapshot` currently calls `self.device.dump_hierarchy()`.

The implementation should first try to use uiautomator2 source-level compression if the installed library supports it, for example by calling `dump_hierarchy(compressed=True)` or equivalent after verifying support. If the call raises `TypeError` or another compatibility error caused by the optional parameter, it should fall back to `dump_hierarchy()`.

This stage is best-effort. It must not make snapshot capture fail merely because a particular uiautomator2 version does not support a compressed argument.

### 2. Output Contract

The returned payload remains:

```python
{"xml": compact_xml}
```

No new top-level field is required in this cycle. The clipping behavior is documented in the Android `uiTree` capability description and in SPEC. This keeps existing evidence artifact consumers compatible.

### 3. Attribute Cleanup

The compact XML should remove attributes that add size but usually do not help target selection.

Remove by default:

- Empty string attributes.
- `index`.
- `package`.
- Default true visibility/enabled state: `enabled="true"`, `displayed="true"`.
- Default false interaction/state fields: `checkable="false"`, `checked="false"`, `clickable="false"`, `focusable="false"`, `focused="false"`, `long-clickable="false"`, `longClickable="false"`, `password="false"`, `scrollable="false"`, `selected="false"`.
- Large optional extras/actions fields if present, unless a later SPEC explicitly requires them.

Keep by default:

- Identity and locator fields: `resource-id`, `resourceId`, `content-desc`, `contentDescription`.
- Visible text fields: `text`, `hint`, `label`, `name`, `value`.
- Structural fields used by agents and debugging: `class`, `className`, `bounds`.
- Non-default important states: `clickable="true"`, `focusable="true"`, `scrollable="true"`, `checked="true"`, `selected="true"`, `password="true"`, `enabled="false"`, `displayed="false"`.

The exact allowlist should live near the Android driver implementation as private module constants or private helper data. It should not be exported through `core.__init__`.

### 4. Text Clipping

The following text-like attributes should be clipped to the first 50 characters:

- `text`
- `content-desc`
- `contentDescription`
- `hint`
- `label`
- `name`
- `value`

Do not append an ellipsis inside the XML attribute in this cycle. The function description and SPEC must state that long text-like attributes are clipped to the first 50 characters. This avoids adding extra characters and keeps equality-based tests deterministic.

### 5. Layout-Only Node Removal

After attributes are cleaned, a node is considered layout-only if it has no meaningful signal beyond structural fields such as class or bounds, and none of its kept attributes identify, describe, or make the element actionable.

Layout-only wrapper nodes should not be retained as nodes. Their compacted children should be lifted to the parent. This preserves meaningful descendants while reducing hierarchy depth.

A node should be retained if any retained attribute provides signal such as:

- Text or content description.
- Resource id.
- Non-default interactive state.
- Non-default visibility/enabled state.

A node with only `class` and `bounds` should usually be removed unless later testing shows that preserving class-only controls is necessary for real target selection.

### 6. Empty Node Deletion

If a node has no retained attributes and no retained descendants after cleanup, it should be dropped.

The root element should remain present so the result is always valid XML when the input was valid XML.

### 7. Error Handling

Snapshot capture should prefer availability over perfect compaction.

- If source-level compression is unsupported, fall back to uncompressed `dump_hierarchy()`.
- If XML parsing fails, return raw XML unchanged.
- If compaction has an unexpected local failure, return raw XML unchanged rather than failing the runner evidence capture.

The implementation should not silently change action results or failure categories for non-observation Android actions.

## Architecture and Module Ownership

Architecture level: Level 3 Layered Application for `core`, unchanged.

Rationale: This change belongs inside the existing Android backend driver because `core` owns concrete driver-backed PlatformTool behavior and evidence sourcing. The compaction is backend-specific normalization of a driver observation, not a new public service or cross-platform abstraction.

Module ownership:

- `core`: Owns the private Android compact XML behavior in `fsq_agent/core/harness/_uiautomator2_driver.py`.
- `models`: Owns the parameter model description and SPEC wording for `AndroidUiTreeParams`; the model remains fieldless.
- `capabilities`: No new metadata mechanism is required. The existing decorated driver method remains the source of the SDK/tool description.
- `config`: No new setting in this cycle.
- `agent`, `cli`, `playground`, `report`, `observation`: No behavior changes expected.

Python package boundaries:

- New helpers, if needed, should be private functions or private methods in `_uiautomator2_driver.py` unless size or testability clearly requires a private sibling module under `core/harness`.
- Do not export compaction helpers from `fsq_agent.core.__init__`.
- Do not import `core.harness._uiautomator2_driver` from unrelated modules for compaction behavior.
- Do not introduce repository, service, or domain layers for this narrow transformation.

## Public Behavior and Interfaces

Public behavior changes:

- Android `uiTree` / canonical `ui_snapshot` returns compact XML instead of raw uiautomator2 XML.
- Automatic Android `ui_snapshot` evidence artifacts also contain compact XML because they call the same driver method.
- The `uiTree` tool description states that layout-only/default data may be removed and long text-like attributes are clipped to 50 characters.

Interfaces that must not change:

- `AndroidUiTreeParams` remains fieldless.
- `ui_snapshot` remains the canonical capability name.
- `uiTree` remains the Android FSQ replay alias.
- Output remains JSON with an `xml` string.
- Evidence artifact kind remains `ui_snapshot`.

## Affected SPEC Files Expected Later

The later `spec-driven` phase should update at least:

- Root `SPEC.md`: Android platform block, if needed, to clarify that Android automatic `ui_snapshot` evidence is compacted but still sourced from the Android UI hierarchy.
- `fsq_agent/core/SPEC.md`: Android platform block describing compact XML behavior, fallback expectations, and ownership in `UiAutomator2AndroidDriver`.
- `fsq_agent/models/SPEC.md`: `AndroidUiTreeParams` description noting the fieldless request and compact/clipped output behavior.

No config SPEC update is expected unless the design changes to expose tunable compaction settings.

## Verification Expectations

Focused verification should include:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_uiautomator2_android_driver.py -q
.\.venv\Scripts\python.exe -m pytest tests/test_android_harness.py tests/test_capabilities.py -q
```

Test coverage should verify:

- Raw minimal XML still returns as valid XML under the same `{"xml": ...}` shape.
- Unsupported source compression falls back to raw `dump_hierarchy()` call.
- Layout-only wrapper nodes are removed while meaningful children remain.
- Empty/default attributes are removed.
- Meaningful locator/actionability attributes are preserved.
- Long text-like attributes are clipped to exactly 50 characters.
- Malformed XML falls back unchanged.
- Android action-space/capability exposure still includes `ui_snapshot` / `uiTree` and does not expose new unsupported actions.

## Follow-Up Strategies Not In This Cycle

These remain viable later strategies after the first compact XML change is measured:

- Hard maximum node count, depth, or byte budget.
- Viewport-only retention based on `bounds` and current screen size.
- Recycler/list sibling deduplication with sample nodes and counts.
- Task-aware attribute retention.
- Snapshot diffing between before/after evidence captures.
- Separate locator-first JSON snapshot for agent planning.

## Open Questions Resolved

- The first cycle is Android-only.
- The first cycle keeps XML output and does not replace it with JSON locators.
- Long text-like attributes are clipped to 50 characters.
- Clipping is documented through tool description and SPEC wording, not through an added XML marker.
- No user-facing config setting is added in the first cycle.
